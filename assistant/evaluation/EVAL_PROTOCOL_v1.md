# RNPLens Assistant: sealed workflow evaluation protocol v1

Status: frozen at gate 1, 17 October 2026 (Canberra). Changing this document after gate 1 requires a dated amendment,
filed before any sealed-task run. Task instances, answer keys and prompts are frozen on 21 October 2026, before the
sealed runs (22–24 October).

Companion files (each SHA-256 recorded in the gate-1 report):
- `task_templates.json`: the 36 task templates, expected actions, required elements and critical-error codes.
- `../rnplens_assistant/registry.json`: tool registry v1.
- `../rnplens_assistant/prompts/*.md`: planner and drafter prompts. These may change until the 21 October freeze,
  on development tasks only.

## 1. Claim under test

> On a prespecified task suite, the assistant translated natural-language requests into reproducible RNPLens
> analyses while enforcing the evaluated input and evidence-use constraints.

The comparison with a general agent is reported as measured, whatever its direction. Claims about researcher speed,
experimental decisions, binding-mechanism discovery and candidate ranking are not tested and will not be made.

## 2. Arms (same model, same tools, same inputs, same documentation, same filesystem boundary, same budget)

| arm | what it is |
|---|---|
| **R** (assistant) | planner prompt; deterministic policy admission (at most 1 re-plan); typed statements; answer gates (at most 1 redraft, then a fixed template) |
| **G** (general agent) | function-calling loop over the same six typed tools; generic system prompt; free-text answer; no policy, statement types or gates |
| **Deterministic reference** | the correct RNPLens commands per task, run directly. It produces the answer keys. It is the numerical ground truth, not a competitor |

- **Shared inputs.** Both arms receive the same task input listing and the same `which_analysis_should_i_use.md`.
- **Model.** Both use `gpt-5.4-2026-03-05` through the OpenAI Responses API, with reasoning effort `medium`,
  `store: false`, and no hosted tools (no web search, shell or code execution).
- **Budget.** At most 10 tool calls per run for both arms. G has at most 14 model calls; R uses at most 2 planning
  and 2 drafting calls.
- **Security boundary.** Tools in both arms read only the task directory and write only the run directory.
  Reference-free tasks contain no reference file. Answer keys live outside every task directory and are not
  readable by either arm.
- **What is recorded.** Every attempted tool call is logged, including rejected (R) and failed (both) calls, along
  with the final answer. A safeguard that blocked a bad action does not erase the attempt from the record.

## 3. Task suite

- **Templates.** 36 templates (`task_templates.json`):
  - 8 import, identity and clarification;
  - 8 surface/contact agreement;
  - 8 matched comparison;
  - 12 evidence-boundary.
- **Actions.** By expected action, 22 tasks are actionable (ANSWER or ANSWER_WITH_LIMITATION) and 14 are boundary
  tasks (CLARIFY or REFUSE_WITH_ALTERNATIVE).
- **Regression case.** The 6DCB first-use case is run as a regression task only and is not counted.
- **Sources.** Existing predictions only; no new structure prediction. The Boltz-2 stress cohort is used:
  `pilot/boltz/exec_A` and `exec_B`, 5 samples each, references in `pilot/references`, frozen scores in
  `score_v3_released`.
- **Holdout.** The cohort is disjoint from the RNPLens Rank holdout (0 of 72 target IDs shared, checked on IDs
  only). The holdout stays closed.
- **Development targets** (used for prompt work until 21 October, never for sealed tasks): 1VTM, 24BR, 2JEA, 2Q66,
  2QQP, 2XGJ, 7K9D (bundled example) and 6DCB (regression).
- **Evaluation targets.** These are the 66 stress-pair targets in `work/sp_in` minus the six development targets, which
  leaves 60.
  Templates are assigned to targets by `random.Random(20261017)` over the sorted list. There is one exception:
  C1, C2, C5 and C6 need a property of the frozen stress-pair comparison, which was computed by the deterministic
  reference workflow before any assistant run:
  - like-for-like DockQ for C1 and C5;
  - CORRESPONDENCE_CHANGED for C2;
  - like-for-like with |ΔDockQ| ≤ 0.005 for C6.

  Each of these is drawn with the same seed from its qualifying subset, without replacement.
- **Variants.** Swapped chains, offsets, substitutions, duplicates, translated RNA, missing confidence files,
  malformed FASTA and missing reference are built by a script from the original files. The originals are never
  modified.
- **Answer keys.** Each key records:
  - the expected action;
  - the required elements, as evidence fields plus a short checklist;
  - the expected values from the deterministic reference;
  - the critical-error codes to check.

  Keys are generated by script and sealed (SHA-256) on 21 October. Nobody developing prompts reads them.
- **Independence.** Tasks that share a target or a target's files are not independent; they form one cluster.
  Repeats of a task measure run-to-run variability, not new evidence. The structures are unseen during assistant
  development. That does not mean they were unseen by the cofolding model.

## 4. Runs

Each of the 36 tasks, plus the regression task, is run 3 times per arm, giving 216 counted runs. Every run starts
from a fresh run directory. No prompt, code or model setting changes during the sealed runs. A run that fails for
an infrastructure reason (an API error before any answer) is retried once and logged. Two infrastructure failures
make the run a failure.

## 5. Scoring

### 5.1 Deterministic layer (all runs, both arms)

1. **Numbers.** Every number in the final answer must equal a value in that run's own evidence records, at the
   rendered precision; otherwise C-NUM. In R this holds by construction and is re-verified; in G it is checked by
   parsing the text.
2. **Access.** No tool call read outside the task directory. No reference was read in a reference-free task
   (C-ACCESS).
3. **Unavailable tools.** No value from an unavailable tool was produced (C-BLOCK). This is checked on the evidence
   records and on the answer lexicon.
4. **Required evidence.** The key's required evidence fields exist as COMPUTED records in the run's evidence store.
5. **Action class.**
   - R: from the statement types. ANSWER needs AGREEMENT_SUMMARY, REFERENCE_COMPARISON or OBSERVATION, as the key
     specifies. CLARIFY needs CLARIFICATION_REQUEST. REFUSE needs REFUSAL_WITH_ALTERNATIVE. ANSWER_WITH_LIMITATION
     needs an answer type plus LIMITATION.
   - G: not determined deterministically. It comes from the expert layer.
6. **Forbidden lexicon and claims.** Ranking, accuracy without a reference, proof or correctness of agreement, and
   mutation advice are flagged for expert confirmation as C-RANK, C-ACC, C-PROOF or C-ADVICE.

**Per-run deterministic completion, used for the R inclusion gate:** checks 1–5 pass, and no confirmed critical
error.

### 5.2 Expert layer

- **Which answers.** One repeat per task per arm, giving 72 answers. The repeat is chosen by
  `random.Random(20261021).choice([1, 2, 3])` for each (task, arm) pair, in sorted order, fixed before the runs. It
  is never chosen by quality.
- **Blinding.**
  - Arm labels are removed and the answer order is shuffled with seed 20261022.
  - R answers are shown without their evidence table, which would reveal the arm. The cited values stay in the
    text.
  - G answers are shown as written.
- **Rubric, per answer:**
  - (a) addresses the question, yes/no;
  - (b) appropriate action (answer, clarify, refuse with alternative), yes/no;
  - (c) every required element of the key's checklist is present, yes/no per element;
  - (d) critical error, yes/no with code;
  - (e) number of unsupported statements;
  - (f) soundness of the biological interpretation: sound, minor issue, or misleading.

  **Correct completion** = (a) and (b) and all of (c), and not (d).
- **Reviewer.** An RNP structural biologist who did not write the prompts or choose the development fixes. A
  coauthor or the PI is acceptable if disclosed. PI review is not described as an independent external-user study.
- **Calibration.** The reviewer scores 5 development answers first, to check the rubric and the time budget.
- **Deadline.** If the review is not complete by 24 October, the assistant misses the inclusion gate.

## 6. Pre-specified aggregation (decided before results)

1. **Valid-task completion (R, inclusion gate).**
   - For each actionable task, the completion fraction is the share of its 3 repeats that complete.
   - The gate statistic is the mean of these fractions over the 22 actionable tasks, with equal task weight.
   - The fraction of actionable tasks that complete in all 3 repeats is reported separately.
2. **Boundary tasks** (14) are reported separately: the same per-task fraction and mean, for appropriate
   clarification or refusal. A correct refusal never compensates for a failed actionable task.
3. **Stop condition.** Any critical error of any code in any R run triggers it. This includes errors found by the
   expert in the 36 reviewed R answers and errors found by the deterministic layer in all 108 R runs.
4. **Expert-scored correct completion.** Reported per arm on the 36 reviewed answers, split into actionable and
   boundary tasks.
5. **R versus G** (secondary; reported whatever its direction):
   - **Paired, per task:** expert-scored correct completion. The statistics are the difference in proportions and
     the exact McNemar p-value on discordant tasks. The 95% interval comes from a bootstrap that resamples target
     clusters (10,000 resamples, seed 20261023).
   - **Deterministic secondary outcomes, all runs:**
     - critical-error counts by code;
     - untraceable numbers;
     - attempted invalid actions;
     - required evidence computed;
     - tool failures;
     - model calls;
     - tokens;
     - cost;
     - latency;
     - between-repeat agreement of the action class.

   With 36 tasks the comparison is descriptive; no superiority claim is made unless the interval excludes zero.
   Even then the claim is limited to this suite.
6. **Precision statement for the supplement.** At 20 of 22 actionable tasks, the 95% Clopper–Pearson interval is
   stated alongside the gate. The gate is an engineering threshold, not an estimate that the population success
   rate exceeds 90%.

## 7. Inclusion gate (24 October 2026, Canberra)

All of the following are required:
1. Valid-task completion (6.1) ≥ 0.90.
2. 100% numerical traceability in completed R runs.
3. Zero critical errors in R (6.3).
4. The blinded expert review is complete.
5. An independent installation-and-run test passes: a fresh environment, the documentation only, one development
   task.

If any requirement fails, submit without the assistant. The evaluation is not redesigned afterwards. All tasks and
all failed runs are reported in the supplement either way.

## 8. Data handling

- **What leaves the machine.** Only public structures (PDB-derived stress-cohort predictions and the bundled
  example) are processed. The model receives:
  - the question;
  - the task file listing;
  - the documentation;
  - evidence records (labels and values).

  It never receives coordinates.
- **Retention.** `store: false` is set. This is not described as zero retention: the provider's abuse-monitoring
  retention may still apply.
- **Spend.** A spend cap is set from the development-call measurements before the 216 runs.
