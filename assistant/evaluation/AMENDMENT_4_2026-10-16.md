# Amendment 4 to protocol v2 (16 October 2026, Canberra): packaging correction, before any sealed trial

Approved by the owner on 16 Oct ("packaging fix before launch, verified by hash").

**Measurement.** On karyon, `rnplens_assistant.ask._doc()` returned 0 characters in the pip-installed package
(installation test folder `install_test_20261016T150445`). The source checkout returned 11,905 characters (sha256
`d1a45b57…4257`).
- **Cause:** the guide was located relative to the source tree. `tools.explain_metric` used the same lookup.
- **Consequence:** the passed installation test had exercised an assistant whose prompt lacked the analysis guide.

**Change.**
- The guide is shipped as package data, as `rnplens_assistant/docs/which_analysis_should_i_use.md`. It is
  byte-identical to `docs/which_analysis_should_i_use.md`, and a test enforces this.
- Both lookups read the packaged copy through `rnplens_assistant/guide.py`. A missing guide raises an error; it is
  never silently empty.

**Proof that the evaluated behaviour is unchanged.**
- Both arms' shared context `ask.doc_text()` has sha256 `a79637fd…ea97` before and after the change, in the source
  configuration.
- `explain_metric("fnat")` output is identical (`1615052ac88cf3f8`).
- `tests/test_guide_packaging.py` pins both values.
- The installation test gains the step `installed_prompt_equals_evaluated`, which requires the same two values from
  the pip-installed copy.
- The 15 development R replays are re-run after the change and must all still match.

**Unchanged.** Every evaluation file listed in `FREEZE_RECORD_SCORING_2026-10-16.md`: the scorer, aggregator,
runner, replay, builder, protocol, templates, schemas, jail and planner prompt. The sealed manifest is also
unchanged. The frozen commit for the assistant code moves from `a7bf44c` to the commit recorded in
`FREEZE_RECORD_ADDENDUM_AMENDMENT_4.md`.
